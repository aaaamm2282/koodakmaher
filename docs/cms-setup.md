# پنل مدیریت محتوا (Decap CMS)

پنل در نشانی `/admin/` سایت است و بدون کدنویسی، این‌ها را ویرایش می‌کند:

| بخش پنل | چه چیزی | فایل |
|---|---|---|
| اطلاعیه‌ها و اخبار | خبر ثبت‌نام، رویداد، اطلاعیه‌ی واحدها | `src/content/news/*.md` |
| مقاله‌ها | یادداشت‌های «دفتر اندیشه‌ها» با منبع و نویسنده | `src/content/blog/*.md` |
| مراکز و واحدها | نشانی، تلفن، ساعت کار، شهریه، ظرفیت، مدارک، عکس‌ها، پرسش‌های هر واحد، نظر والدین | `src/content/units/*.json` |
| تنظیمات عمومی | نام و شعار، شهر، مجوزها، عکس یا ویدیوی صفحه اول، شبکه‌های اجتماعی، کارگاه‌ها، مراحل ثبت‌نام، پرسش‌های عمومی | `src/content/settings/*.json` |

متن اصلی صفحه‌ها (متد، مسیر، درباره ما و ...) عمداً در پنل نیست، چون طبق `docs/content-brief.md` تنظیم شده و تغییرش باید با بازبینی انجام شود.

## قاعده‌هایی که پنل خودش رعایت می‌کند

- **خالی یعنی «در حال تکمیل».** هر فیلدی که خالی بماند، در سایت برچسب «در حال تکمیل» می‌گیرد و در داده‌ی گوگل نمی‌آید. چیزی را حدسی پر نکنید.
- **عکس بدون رضایت‌نامه نشان داده نمی‌شود.** هر عکسِ واحد یک گزینه‌ی «برای همه‌ی افراد داخل عکس رضایت‌نامه‌ی کتبی داریم» دارد. تا روشن نشود، عکس در سایت نیست.
- **نظر والدین فقط با اجازه.** گزینه‌ی «اجازه‌ی انتشار گرفته شده است» باید روشن باشد. نظر ساختگی ممنوع است.
- **مقاله‌ی پیش‌نویس منتشر نمی‌شود.** گزینه‌ی «پیش‌نویس» برای مقاله‌ی تازه به‌طور پیش‌فرض روشن است.
- **نشانی صفحه (slug) انگلیسی است** و بعد از انتشار نباید عوض شود.

## نقش‌ها: نویسنده پیش‌نویس می‌گذارد، مدیر منتشر می‌کند

پنل در حالت «گردش کار» است: هر نوشته سه مرحله دارد: پیش‌نویس، آماده بررسی، آماده انتشار. هر مرحله در گیت‌هاب یک «درخواست ادغام» (Pull Request) است و تا ادغام نشود، روی سایت نمی‌رود.

برای اینکه فقط مدیر بتواند منتشر کند:

1. مدیر (صاحب مخزن `aaaamm2282/koodakmaher`) در گیت‌هاب: **Settings ← Collaborators** و نویسنده‌ها را با دسترسی **Write** دعوت کند.
2. در **Settings ← Branches ← Add branch ruleset** (یا Branch protection rule) برای شاخه‌ی `main`:
   - **Require a pull request before merging** روشن، با **Required approvals: 1**.
   - صاحب مخزن در فهرست **Bypass list** باشد تا خودش بتواند منتشر کند.
3. از این به بعد نویسنده تا «آماده انتشار» جلو می‌رود. دکمه‌ی «انتشار» برای او خطا می‌دهد و مدیر نوشته را می‌بیند و منتشر می‌کند.

## ویرایش روی رایانه‌ی خودتان (بدون ورود)

```bash
npm install
npx -y decap-server@3.11.6   # در یک پنجره
npm run dev                  # در پنجره‌ی دیگر
```

سپس `http://localhost:4321/admin/` را باز کنید و «وارد شدن» را بزنید. تغییرها مستقیم در فایل‌های پروژه ذخیره می‌شود و باید آن‌ها را commit کنید.

## راه‌اندازی ورود آنلاین (یک بار)

پنل با حساب گیت‌هاب وارد می‌شود. گیت‌هاب برای این کار یک «واسط ورود» کوچک لازم دارد. کد آن در `scripts/cms-auth/worker.js` است و روی Cloudflare Workers (رایگان) اجرا می‌شود.

1. **ساخت برنامه‌ی OAuth در گیت‌هاب:** Settings ← Developer settings ← OAuth Apps ← New OAuth App
   - Application name: `Koodak Maher CMS`
   - Homepage URL: `https://mahermana.com`
   - Authorization callback URL: `https://koodakmaher-cms-auth.<subdomain>.workers.dev/callback`
   - بعد از ساخت، **Client ID** را بردارید و یک **Client secret** بسازید.
2. **راه‌اندازی واسط:** در پوشه‌ی `scripts/cms-auth`:
   ```bash
   npx wrangler login
   # در wrangler.toml مقدار GITHUB_CLIENT_ID و ALLOWED_ORIGIN را بنویسید
   npx wrangler secret put GITHUB_CLIENT_SECRET   # رمز را اینجا وارد کنید، نه در هیچ فایلی
   npx wrangler deploy
   ```
3. **وصل کردن پنل:** در `public/admin/config.yml` خط `base_url` را از حالت توضیح خارج کنید و نشانی Worker را بنویسید.
4. اگر سایت روی Netlify میزبانی شود، به‌جای مرحله‌های ۱ تا ۳ می‌توانید از ورود خود Netlify استفاده کنید.

**امنیت:** رمز برنامه‌ی OAuth فقط در تنظیمات Cloudflare است. واسط فقط به سایتی که در `ALLOWED_ORIGIN` نوشته شده توکن می‌دهد و با `state` جلوی جعل درخواست را می‌گیرد.

## بعد از انتشار، سایت چطور به‌روز می‌شود؟

انتشار در پنل یعنی تغییر در شاخه‌ی `main`. ساخت و بارگذاری سایت به میزبان بستگی دارد (کار شماره ۶ فهرست شما: دامنه و هاست):

- **Cloudflare Pages یا Netlify:** مخزن را وصل کنید؛ با هر تغییر در `main` خودکار ساخته می‌شود. فرمان ساخت `npm run build` و پوشه‌ی خروجی `dist`.
- **هاست cPanel ایرانی:** گردش کار آماده‌ی GitHub Actions (`.github/workflows/deploy.yml`) پس از هر تغییر سایت را می‌سازد و با FTP رمزنگاری‌شده روی هاست بارگذاری می‌کند، و هر روز صبح مقاله‌هایی را که تاریخ انتشارشان رسیده منتشر می‌کند. نام کاربری و رمز FTP فقط در **Settings ← Secrets and variables ← Actions** مخزن ذخیره می‌شود. راه‌اندازی: [deploy.md](deploy.md)، بخش ۳.

## عکس‌ها

- عکس‌ها در `src/assets/uploads` ذخیره می‌شوند و سایت خودش نسخه‌های AVIF و WebP در اندازه‌های مختلف می‌سازد. لازم نیست عکس را کوچک کنید؛ فقط کمتر از ۱۰ مگابایت باشد.
- برای هر عکس «توضیح تصویر» یک جمله‌ی فارسی است درباره‌ی آنچه دیده می‌شود. نام کودک ننویسید.
- فهرست عکس‌هایی که لازم است: `docs/photo-shot-list.md`.

```bash
npm pack decap-cms@<version>

tar -xzf decap-cms-<version>.tgz
mkdir -p public/admin/vendor/decap-cms-<version>
cp package/dist/decap-cms.js package/dist/*.decap-cms.js package/dist/*.wasm package/dist/decap-cms.js.LICENSE.txt public/admin/vendor/decap-cms-<version>/
# سپس نشانی اسکریپت را در public/admin/index.html عوض کنید و پوشه‌ی قبلی را پاک کنید
```
