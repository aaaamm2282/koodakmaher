# گزارش ماهانه‌ی سایت

هفته‌ی اول هر ماه شمسی، برای ماه قبل؛ حدود یک ساعت. نتیجه یک فایل است با این بخش‌ها: کلیک و نمایش در گوگل و تغییرش از ماه قبل، جایگاه عبارت‌های هدف هر صفحه، مقاله‌ها، تعداد فرم‌ها به تفکیک واحد و منبع، نظرهای نقشه‌ها، آمار بازدید، و کارهای پیشنهادی ماه بعد که از خود عددها درمی‌آید.

بیشتر گزارش را دستور `npm run report:monthly` از دو خروجی می‌سازد؛ دو بخش (نقشه‌ها و آمار بازدید) را دستی پر می‌کنید.

## ۱. خروجی سرچ کنسول

1. [search.google.com/search-console](https://search.google.com/search-console) ← ویژگی سایت ← **Performance** (عملکرد) ← **Search results**.
2. **Date** ← **Custom**: از روز اول تا روز آخر ماه قبل. دستور گزارش تاریخ میلادی همان ماه را هم چاپ می‌کند (مثلاً آبان ۱۴۰۵ = ۲۰۲۶-۱۰-۲۳ تا ۲۰۲۶-۱۱-۲۱). گزینه‌ی **Compare** را روشن نکنید.
3. بالای صفحه ← **Export** ← **Download CSV**. فایل ZIP را باز کنید (مثلاً در `Downloads/gsc-1405-08`). همه‌ی فایل‌هایش را نگه دارید؛ گزارش خودش پیدا می‌کند کدام پرسمان‌ها (Queries)، صفحه‌ها (Pages)، روزها (Dates) و دستگاه‌ها (Devices) است، چه زبان سرچ کنسول انگلیسی باشد چه فارسی.

داده‌ی سرچ کنسول دو سه روز عقب است؛ گزارش را از روز سوم ماه به بعد بسازید.

همان‌جا، بدون خروجی، این‌ها را هم نگاه کنید و اگر چیزی غیرعادی بود در بخش «کارهای ماه بعد» بنویسید:

| کجا | چه چیزی را ببینید |
|---|---|
| **Indexing ← Pages** | تعداد صفحه‌های ایندکس‌شده نزدیک تعداد صفحه‌های نقشه‌ی سایت باشد. «Not found (404)»: نشانی قدیمی‌ای که ریدایرکت ندارد (در پنل اضافه کنید). «Crawled - currently not indexed» برای صفحه‌ی مهم: URL Inspection ← Request indexing. |
| **Indexing ← Sitemaps** | وضعیت `sitemap-index.xml` «Success» باشد. |
| **Experience ← Core Web Vitals** | بخش Mobile همه «Good». برای سایت کم‌بازدید ممکن است «Not enough data» باشد که ایرادی نیست. |
| **Security & Manual actions** | «No issues detected». |
| **Links** | سایت‌های تازه‌ای که به سایت پیوند داده‌اند. |

## ۲. فایل‌های فرم از هاست

cPanel ← File Manager ← پوشه‌ی فرم‌ها (همان `storage_dir` در `form-config.php`، مثلاً `/home/نام-کاربری/form-data`) ← فایل‌های `register.csv`، `contact.csv`، `careers.csv` و `notify.csv` را انتخاب کنید ← **Compress** ← فایل فشرده را بگیرید و روی کامپیوتر باز کنید (مثلاً `Downloads/forms-1405-08`).

این فایل‌ها نام و تلفن والدین را دارند:

- پوشه‌شان را **داخل پوشه‌ی پروژه‌ی سایت نگذارید** و بعد از ساختن گزارش پاکشان کنید.
- گزارش فقط می‌شمارد. نام، تلفن، پیام یا هیچ پاسخ آزادی در آن نوشته نمی‌شود. پاسخ‌های «چطور با ما آشنا شدید؟» در گروه‌هایی مثل «اینستاگرام» یا «دوستان و آشنایان» شمرده می‌شوند.

## ۳. ساختن گزارش

```bash
npm run report:monthly -- --gsc ~/Downloads/gsc-1405-08 --forms ~/Downloads/forms-1405-08
```

- بدون `--month`، گزارش برای ماه قبل ساخته می‌شود. برای ماه دیگر: `--month 1405-08`.
- هر کدام از `--gsc` یا `--forms` را می‌شود نداد؛ بخش مربوطش خالی می‌ماند.
- خروجی: `reports/1405-08.md` برای خواندن و `reports/1405-08.json` که گزارش ماه بعد برای ستون «تغییر از ماه قبل» می‌خواند. پوشه‌ی `reports/` در GitHub بارگذاری نمی‌شود (مخزن عمومی است). فایل `.md` را با هر ویرایشگری باز کنید؛ در VS Code با Ctrl+Shift+V مرتب دیده می‌شود.

هشدارهایی که ممکن است ببینید:

| هشدار | یعنی |
|---|---|
| بازه‌ی خروجی سرچ کنسول با ماه یکی نیست | در مرحله‌ی ۱ تاریخ را روی همان ماه نگذاشته‌اید (مثلاً «Last 28 days» مانده). خروجی را دوباره بگیرید. |
| فایل Dates نبود | جمع کلیک و نمایش از جدول پرسمان‌ها حساب شده و کمتر از واقعی است، چون گوگل جست‌وجوهای کم‌تکرار را در آن جدول نمی‌آورد. |
| دو ستون کلیک دارد | خروجی با Compare گرفته شده. بدون آن دوباره بگیرید. |

## ۴. بخش‌های دستی

**نقشه‌ها و نظرها.** برای هر واحد در گوگل‌مپ، نشان و بلد: امتیاز، تعداد نظرها، نظرهای تازه‌ی این ماه و نظرهای بی‌پاسخ. به هر نظر تازه همان هفته پاسخ بدهید؛ نمونه‌ی پاسخ‌ها و پیام درخواست نظر در [local-profiles.md](local-profiles.md). برای نظر دادن هدیه یا تخفیف ندهید؛ گوگل نظرهای این‌چنینی را حذف می‌کند.

**آمار بازدید.** از GA4 یا Umami، هر کدام که راه افتاده است ([forms-setup.md](forms-setup.md)، بخش ۹):

| شاخص | GA4 | Umami |
|---|---|---|
| بازدیدکننده و منبع‌های ورود | Reports ← Acquisition ← Traffic acquisition | Overview و Referrers |
| فرم‌های فرستاده‌شده به تفکیک فرم و واحد | Reports ← Engagement ← Events ← `generate_lead` (پارامترهای `form` و `unit`) | Events |
| کلیک روی تلفن و نقشه | رویدادهای `click_phone` و `click_map` | Events |
| صفحه‌های ۴۰۴ | رویداد `page_not_found`، پارامتر `path` | Events |

عدد `generate_lead` باید نزدیک جمع فرم‌های بخش «فرم‌ها» باشد. اگر کمتر است، طبیعی است: کسانی که «درخواست ردیابی نشدن» را در مرورگر روشن کرده‌اند یا مسدودکننده‌ی تبلیغات دارند در آمار شمرده نمی‌شوند، ولی فرمشان در فایل هست.

نشانی‌های پرتکرار `page_not_found` را در پنل مدیریت ← تنظیمات عمومی ← ریدایرکت‌ها به صفحه‌ی درستشان وصل کنید ([migration.md](migration.md)).

## ۵. خواندن گزارش

- **جایگاه کمتر بهتر است.** ۱ تا ۳ یعنی بالای نتایج؛ ۴ تا ۱۰ صفحه‌ی اول؛ ۱۱ تا ۲۰ صفحه‌ی دوم. بیشترین سود معمولاً از عبارت‌هایی است که در صفحه‌ی اول یا دوم‌اند و نمایش خوبی دارند؛ گزارش همین‌ها را در «کارهای ماه بعد» می‌آورد.
- **«دقیق» و «همه».** «دقیق» همان عبارت نقشه‌ی کلمات کلیدی است. «همه» هر جست‌وجویی است که همه‌ی کلمه‌های عبارت را دارد (مثل «کودکستان خوب نزدیک من» برای «کودکستان»)؛ تصویر کامل‌تری است.
- **یک ماه را مبنا نگیرید.** عددها از ماهی به ماه دیگر بالا و پایین می‌روند، به‌خصوص در ماه‌های اول بعد از راه‌اندازی که گوگل نشانی‌های تازه را جایگزین قدیمی‌ها می‌کند. روند سه ماه را ببینید، و وقتی یک سال گذشت، هر ماه را با همان ماه سال قبل مقایسه کنید (فصل ثبت‌نام).
- **نرخ کلیک پایین** برای صفحه‌ای که در صفحه‌ی اول نتایج است یعنی عنوان و توضیحی که گوگل نشان می‌دهد مخاطب را قانع نمی‌کند. عنوان و توضیح هر صفحه در `src/data/keyword-map.json` است.
- **جست‌وجوهای بی‌صاحب** (در «کارهای ماه بعد»): پرسش‌هایی که والدین می‌پرسند و هیچ صفحه‌ای برایشان نیست. پیش از نوشتن مقاله، به نقشه‌ی کلمات کلیدی و [تقویم مقاله‌ها](content-calendar.md) اضافه شوند تا با صفحه‌ی دیگری رقابت نکنند.
- **نشانی‌های سایت قبلی** که هنوز در نتایج‌اند، در ماه‌های اول طبیعی‌اند. ریدایرکت‌ها را نگه دارید ([migration.md](migration.md)، «بعد از راه‌اندازی»).
